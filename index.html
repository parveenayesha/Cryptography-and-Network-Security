OUTCOME-BASED LEARNING

Course outcomes

The five outcomes below preserve the intent of the supplied syllabus and express it as observable learning targets for teaching and assessment. Faculty approval is required before formal adoption.

CO1 · K2

Recognise threat sources

Identify and classify common information and network threat sources.

CO2 · K3/K5

Select protections

Select appropriate security services, mechanisms and algorithms for a given threat and context.

CO3 · K6

Design a security solution

Design an end-to-end security solution for a given application system.

CO4 · K3

Apply security concepts

Apply cryptographic and network security concepts to protect communication privacy and data.

CO5 · K4

Analyse network threats

Analyse threats across network, transport, wireless, e-mail and IP security contexts.

Bloom's key: K1 Remember · K2 Understand · K3 Apply · K4 Analyse · K5 Evaluate · K6 Create.

Explore all five units

The topic descriptions match the uploaded AICTE model curriculum extract. Expand each unit for the detailed topic list.

Unit I Security Concepts and Classical Cryptography

Introduction and need for security; security approaches and principles; security attacks, services and mechanisms; network security model; cryptography concepts; plaintext/ciphertext; substitution and transposition; encryption/decryption; symmetric and asymmetric key cryptography.

CO1CO2CO5

Unit II Symmetric and Public-Key Ciphers

Block-cipher principles; DES, AES, Blowfish, RC5, IDEA; block-cipher operation; stream ciphers and RC4; public-key cipher principles; RSA algorithm; Diffie–Hellman key exchange.

CO2CO4CO5

Unit III Hashes, Message Authentication and Key Management

Cryptographic hash functions; RSA algorithm as printed in the unit heading; message authentication; SHA-512; authentication requirements; HMAC and CMAC; digital signatures; symmetric/asymmetric key distribution; public-key distribution; Kerberos; X.509 authentication service.

CO2CO3CO4

Unit IV Transport-Level and Wireless Network Security

Web security considerations; SSL/TLS; HTTPS; Secure Shell (SSH); wireless network security; mobile-device security; IEEE 802.11 wireless LAN; IEEE 802.11i wireless LAN security.

CO2CO3CO4CO5

Unit V E-Mail Security and IP Security

Pretty Good Privacy (PGP); S/MIME; IP security overview and architecture; Authentication Header (AH); Encapsulating Security Payload (ESP); combining security associations.

INTERACTIVE LEARNING RESOURCE

Caesar cipher lab

This small simulation demonstrates classical substitution. It is a learning activity only; Caesar cipher is not secure for real-world communication.

OUTPUT

KHOOR ZRUOG

What to notice

  1. Letters shift within A–Z and wrap around at Z.
  2. Spaces and punctuation remain unchanged.
  3. The same key reverses the operation when decrypting.
Never use a Caesar cipher to protect real passwords, personal data or institutional records.

RESPONSIBLE AI

Use AI as a learning partner, not a substitute

Allowed with disclosure

Brainstorm study questions, explain a concept in simpler language, generate practice cases, or review grammar. Verify all cryptographic algorithms and protocol claims against course resources.

Not allowed

Submitting AI output as wholly original work, using AI to impersonate another learner, inventing references, sharing passwords or personal student data, or using tools to attack real systems without written authorization.

Assessment that values reasoning

Use viva questions, stepwise working, live cipher exercises, threat-model justification, unseen scenarios, oral reflection and version history. Ask students to disclose tools and prompts used.
